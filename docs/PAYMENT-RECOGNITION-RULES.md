# 通用交易识别规则

本文记录当前 Android 客户端基于 `assists-base` 的自动记账规则。当前采集入口只接纳经活动根节点验证的支付宝窗口；交易正文仍按通用规则解析，不依赖支付宝专属控件，也不使用截图或 OCR。

## 1. 采集边界

- 用户必须先开启自动记账；开关默认关闭，与无障碍授权和服务连接状态分别保存与展示。
- `AssistsService` 接收无障碍事件；支付宝候选事件以及包名缺失的窗口集合变化事件进入采集波次，采集时再次验证当前活动根节点属于支付宝。
- 排除 BKS 自身。只读取当前活动窗口中可见、非密码、非可编辑节点的文字，最多 512 个节点、24 层和 16 KiB。
- 不点击、不滚动、不启动其他应用、不截图、不执行 OCR。
- 同一包名和窗口 ID 成功创建后保持去重，空文本、局部节点、处理中或广告刷新导致的解析失败不解除去重。仅看到独立的确认付款、待支付或支付密码提示等新付款标志，且正文不含完成状态时，重新开放该应用已记录的窗口；新付款页与结果页可以使用不同窗口 ID。落库失败仍释放窗口供重试，进行中的落库完成后再应用重置。
- 不按相同金额或商户合并真实交易，不查询或修改待确认候选和历史记录；当前去重状态仅在服务会话内按窗口保存，窗口 ID 改变或服务重连不具备跨窗口、跨进程幂等保证。

## 2. 同时满足的准入条件

页面必须同时具备：

1. 明确完成状态，例如`支付成功`、`付款成功`、`收款成功`、`退款到账`或`交易完成`。
2. 唯一交易金额。金额必须带`¥`、`￥`或`元`；同一金额重复展示不算冲突，不同金额同时出现则拒绝。
3. 唯一资金方向。收入/收款/退款属于流入，支付/付款/扣款/支出属于流出；两种方向同时出现则拒绝。
4. 至少一个交易上下文字段，例如商户、收款方、付款方、交易对象、商品、订单、交易单号、支付方式或交易时间。

商户优先从`商户`、`收款方`等显式标签提取；同行字段需要标签位于行首并有冒号或空格分隔，避免把营销文案中的“商品”等字样当作字段。标签缺失时，只在独立完成状态行之后、首个交易上下文字段之前跳过金额、操作文案、明确营销文案和支付方式，取首个有效独立文本，并折叠连续空白。支付方式按完整名称及银行卡类型/尾号形式排除，不因商户名包含“花呗”等字样就排除。无法提取商户时使用`其他应用支付`，但仍必须满足其他交易上下文要求，首次成功采集不会等待商户补齐。

## 3. 硬性拒绝

以下任一情况出现即拒绝，不因同时存在正面词而放行：

- 付款发起或密码页面：`确认付款`、`立即支付`、`继续支付`、`输入密码`、`支付密码`。
- 未完成状态：`待支付`、`待付款`、`处理中`。
- 失败或取消：`支付失败`、`付款失败`、`交易失败`、`已取消`、`交易取消`。
- 缺少金额、完成状态、明确方向或交易上下文。
- 出现多个不同金额或流入/流出方向冲突。

未命中内容、原始页面文字和无关页面信息只在内存中短暂存在，不写入数据库、诊断日志、备份或网络请求。

## 4. 候选输出

每个新候选使用：

- 经实际采集根节点包名映射的支付来源；当前支付宝采集写入 `PaymentSource.ALIPAY`，界面显示`支付宝`。映射器为后续入口保留未知包名到 `PaymentSource.OTHER` 的回退，但当前非支付宝根节点会在识别前被拒绝。
- `CaptureReason.ACCESSIBILITY_AUTO`，界面显示`支付结果自动捕获`。
- `ConfidenceState.NEEDS_REVIEW`。
- 资金账户为空，不自动创建或选择账户。
- 原始证据文本为空，仅保存金额、方向、商户/回退标题、时间和规范化解析字段。

候选经现有本地分类和 `ReviewQueuePersistence` 进入待确认队列。本地规则仅按商户匹配：英文逗号分隔的关键词采用“任一包含即命中”，来源仍由实际根节点包名决定，交易类型仍由本节识别规则决定。用户规则优先于未修改的内置规则；建议分类必须解析到当前系统或自定义分类的真实 ID，否则保持未分类。用户确认前不会写入账本。

## 5. 实现依据

- 无障碍入口：[`BillSyncAccessibilityService.kt`](../apps/android/src/main/java/com/bks/model/platform/billsync/BillSyncAccessibilityService.kt)
- 通用解析：[`BillPageParser.kt`](../apps/android/src/main/java/com/bks/model/domain/billsync/BillPageParser.kt)
- 候选生成：[`BillSyncPipeline.kt`](../apps/android/src/main/java/com/bks/model/domain/billsync/BillSyncPipeline.kt)
- 待确认写入：[`BillSyncCaptureProcessor.kt`](../apps/android/src/main/java/com/bks/model/application/billsync/BillSyncCaptureProcessor.kt)

`PaymentSource.WECHAT` 已保留包名映射，但当前自动采集入口尚未接纳微信窗口；通知捕获和账单同步枚举值仍用于兼容相应历史记录。
